# 工作原理

本頁面向希望瞭解實現細節嘅讀者。日常使用無需閲讀。

## 多人聯機

### 整體結構

一次遊戲連接依次經過以下環節：

1. **好友嘅遊戲** 從局域網世界列表進入房間，連接到本機嘅 `127.0.0.1` 端口；
2. **好友嘅聯機組件** 將連接送入加密虛擬網絡，以直連或中轉嘅方式抵達房主；
3. **房主嘅連接網關** 識別加入者身份，決定放行或拒絕；
4. **房主嘅局域網世界** 接受連接，遊戲開始。

此外，雙方嘅聯機組件都會連接聯機節點，但節點僅用於互相發現；房主一側嘅房間服務負責同步玩家列表。

### 邀請碼與虛擬網絡

每個房間對應一個獨立嘅加密虛擬網絡。邀請碼嘅 16 個字符同時編碼咗該網絡嘅名稱與密鑰：前半部分決定網絡名稱，後半部分決定密鑰。因此，僅憑邀請碼就可以進入對應嘅網絡，而唔持有邀請碼嘅人既冇辦法發現、都冇辦法加入該房間。邀請碼帶有校驗，輸入錯誤時會被立即識別。

網絡由一個開源嘅聯機組件承載。佢喺首次使用時按需下載，每個文件都與內置嘅 SHA-256 值逐一比對，任何鏡像都冇辦法替換成經過修改嘅程序。聯機組件以獨立進程運行，並被放入一個 Windows 作業對象中：Campfire 一旦退出，即使係意外崩潰，組件進程亦會隨之結束，唔會喺後台殘留。

### 發現房主嘅世界

房主無需手動填寫端口。Campfire 讀取系統中喺度監聽嘅 TCP 端口表，篩選出屬於 Java 進程嘅端口，並逐個喺本機發送 Minecraft 狀態查詢，從而識別出局域網世界。呢種方式唔需要監聽網絡廣播，因此唔會觸發 Windows 防火牆嘅詢問；喺本機運行嘅專用服務器亦能以同樣方式被發現。

### 令房間出依家局域網列表中

好友一側，Campfire 喺本機打開一個端口，經虛擬網絡轉發到房主嘅世界，並以 Minecraft 原生嘅「對局域網開放」廣播格式喺本機發布該世界。於是房間會直接出依家多人遊戲頁面底部嘅局域網世界列表中。

從列表進入不僅更加方便，都係離線賬號可以加入嘅前提：房主以正版賬號開放局域網時，遊戲會校驗每位加入者嘅身份，而只有從局域網列表選中嘅世界先會喺校驗失敗時繼續連接。

### 房間服務

房主一側運行一個輕量嘅房間服務。加入者通過佢確認已到達正確嘅房間、獲取遊戲端口，並同步玩家列表、名稱與頭像信息。所有消息都喺虛擬網絡內部傳輸。

### 連接網關

房主嘅世界並唔直接暴露畀虛擬網絡。訪客嘅連接首先到達房主本機嘅連接網關，網關解析 Minecraft 登錄階段嘅數據包，以識別加入者嘅身份。被拉黑嘅玩家會喺登錄時被拒絕，被移出嘅玩家會收到斷開連接嘅數據包。

### 遊戲內房間信息

正常嘅局域網連接喺登錄後即被加密，外部程序冇辦法向其中插入內容。為咗喺聊天欄與 Tab 列表中顯示房間信息，Campfire 會將一個小型 Java 組件附加到房主嘅遊戲進程中，由遊戲服務端自己發送歡迎消息與頁眉頁腳。該組件唔關閉正版驗證，都唔讀取任何登錄憑據。附加失敗時，Campfire 會自動退回僅喺局域網列表中顯示信息。

### 讀取遊戲賬號

每款啟動器都會通過命令行將玩家名稱、UUID 與賬號類型傳畀遊戲。Campfire 從運行中游戲嘅命令行讀取呢三項信息，因此與所用嘅啟動器無關，都唔會接觸任何登錄憑據。

## 啟動器修復

### 定位修改點

Campfire 使用 .NET 程序集讀寫庫解析啟動器，依據**方法名稱與代碼特徵**定位需要修改嘅方法，而非依賴固定嘅文件偏移。呢使得啟動器嘅後續小版本喺結構唔變時通常仍可修復；一旦特徵冇辦法匹配，Campfire 會判定為「暫唔支持」，唔做任何修改。

| 修復項 | 修改嘅方法 | 修改方式 |
| --- | --- | --- |
| Minecraft 版本列表 | `PageDownloadInstall.LoaderInit` | 令下載頁重新綁定版本列表加載器 |
| 手動安裝整合包 | `ModModpack.ModpackInstall()` | 恢復文件選擇，並喺後台線程中安裝 |
| 整合包安裝 | `ModModpack.ModpackInstall(File, …)` | 按識別出嘅整合包格式調用對應嘅安裝方法 |
| 停用自動更新 | `ModSecret.UpdateStart` | 更新入口直接返回 |
| 地區限制 | `RegionAssessment.get_IsRestricted` | 判定方法直接返回 `false`；下載、安裝、補全等入口均讀取呢一屬性 |

### 單文件包嘅原地改寫

部分啟動器以 .NET 單文件包嘅形式發佈。Campfire 會先喺包內定位目標程序集，再將相關方法嘅方法體原地改寫。文件大小與打包佈局都保持唔變，無需重新打包。

### 寫入流程

1. 讀取啟動器並定位全部修改點；
2. 喺內存中生成修復後嘅文件；
3. 重新加載生成結果，逐項確認每個修改點均已生效；
4. 將原文件備份為 `.bak`；
5. 寫入修復後嘅文件。

任一步驟失敗，原文件都保持唔變。再次檢測同一啟動器時，Campfire 可以識別其已修復嘅狀態。

## 更新簽名

正式版嘅每個更新包都使用 ECDSA P-256 私鑰簽名，對應嘅公鑰內置喺程序中。Campfire 只安裝簽名校驗通過嘅更新包；即使下載渠道被篡改，未經簽名嘅程序都冇辦法被安裝。
