# 工作原理

本頁面向希望瞭解實現細節的讀者。日常使用無需閱讀。

## 多人連線

### 整體結構

一次遊戲連線依次經過以下環節：

1. **好友的遊戲** 從區域網世界列表進入房間，連線到本機的 `127.0.0.1` 埠；
2. **好友的連線元件** 將連線送入加密虛擬網路，以直連或中轉的方式抵達房主；
3. **房主的連線閘道器** 識別加入者身份，決定放行或拒絕；
4. **房主的區域網世界** 接受連線，遊戲開始。

此外，雙方的連線元件都會連線連線節點，但節點僅用於互相發現；房主一側的房間服務負責同步玩家列表。

### 邀請碼與虛擬網路

每個房間對應一個獨立的加密虛擬網路。邀請碼的 16 個字元同時編碼了該網路的名稱與金鑰：前半部分決定網路名稱，後半部分決定金鑰。因此，僅憑邀請碼即可進入對應的網路，而不持有邀請碼的人既無法發現、也無法加入該房間。邀請碼帶有校驗，輸入錯誤時會被立即識別。

網路由一個開源的連線元件承載。它在首次使用時按需下載，每個檔案都與內建的 SHA-256 值逐一比對，任何映象都無法替換成經過修改的程式。連線元件以獨立程序執行，並被放入一個 Windows 作業物件中：Campfire 一旦退出，即使是意外崩潰，元件程序也會隨之結束，不會在後臺殘留。

### 發現房主的世界

房主無需手動填寫埠。Campfire 讀取系統中正在監聽的 TCP 埠表，篩選出屬於 Java 程序的埠，並逐個在本機發送 Minecraft 狀態查詢，從而識別出局域網世界。這種方式不需要監聽網路廣播，因此不會觸發 Windows 防火牆的詢問；在本機執行的專用伺服器也能以同樣方式被發現。

### 讓房間出現在區域網列表中

好友一側，Campfire 在本機開啟一個埠，經虛擬網路轉發到房主的世界，並以 Minecraft 原生的「對區域網開放」廣播格式在本機發布該世界。於是房間會直接出現在多人遊戲頁面底部的區域網世界列表中。

從列表進入不僅更加方便，也是離線賬號能夠加入的前提：房主以正版賬號開放區域網時，遊戲會校驗每位加入者的身份，而只有從區域網列表選中的世界才會在校驗失敗時繼續連線。

### 房間服務

房主一側執行一個輕量的房間服務。加入者通過它確認已到達正確的房間、獲取遊戲埠，並同步玩家列表、名稱與頭像資訊。所有訊息都在虛擬網路內部傳輸。

### 連線閘道器

房主的世界並不直接暴露給虛擬網路。訪客的連線首先到達房主本機的連線閘道器，閘道器解析 Minecraft 登入階段的資料包，以識別加入者的身份。被拉黑的玩家會在登入時被拒絕，被移出的玩家會收到斷開連線的資料包。

### 遊戲內房間資訊

正常的區域網連線在登入後即被加密，外部程式無法向其中插入內容。為了在聊天欄與 Tab 列表中顯示房間資訊，Campfire 會將一個小型 Java 元件附加到房主的遊戲程序中，由遊戲服務端自己傳送歡迎訊息與頁首頁尾。該元件不關閉正版驗證，也不讀取任何登入憑據。附加失敗時，Campfire 會自動退回僅在區域網列表中顯示資訊。

### 讀取遊戲賬號

每款啟動器都會通過命令列把玩家名稱、UUID 與賬號型別傳給遊戲。Campfire 從執行中游戲的命令列讀取這三項資訊，因此與所用的啟動器無關，也不會接觸任何登入憑據。

## 啟動器修復

### 定位修改點

Campfire 使用 .NET 程式集讀寫庫解析啟動器，依據**方法名稱與程式碼特徵**定位需要修改的方法，而非依賴固定的檔案偏移。這使得啟動器的後續小版本在結構不變時通常仍可修復；一旦特徵無法匹配，Campfire 會判定為「暫不支援」，不做任何修改。

| 修復項 | 修改的方法 | 修改方式 |
| --- | --- | --- |
| Minecraft 版本列表 | `PageDownloadInstall.LoaderInit` | 讓下載頁重新繫結版本列表載入器 |
| 手動安裝整合包 | `ModModpack.ModpackInstall()` | 恢復檔案選擇，並在後臺執行緒中安裝 |
| 整合包安裝 | `ModModpack.ModpackInstall(File, …)` | 按識別出的整合包格式呼叫對應的安裝方法 |
| 停用自動更新 | `ModSecret.UpdateStart` | 更新入口直接返回 |
| 地區限制 | `RegionAssessment.get_IsRestricted` | 判定方法直接返回 `false`；下載、安裝、補全等入口均讀取這一屬性 |

### 單檔案包的原地改寫

部分啟動器以 .NET 單檔案包的形式釋出。Campfire 會先在包內定位目標程式集，再將相關方法的方法體原地改寫。檔案大小與打包佈局都保持不變，無需重新打包。

### 寫入流程

1. 讀取啟動器並定位全部修改點；
2. 在記憶體中生成修復後的檔案；
3. 重新載入生成結果，逐項確認每個修改點均已生效；
4. 將原檔案備份為 `.bak`；
5. 寫入修復後的檔案。

任一步驟失敗，原檔案都保持不變。再次檢測同一啟動器時，Campfire 能夠識別其已修復的狀態。

## 更新簽名

正式版的每個更新包都使用 ECDSA P-256 私鑰簽名，對應的公鑰內建在程式中。Campfire 只安裝簽名校驗通過的更新包；即使下載渠道被篡改，未經簽名的程式也無法被安裝。
